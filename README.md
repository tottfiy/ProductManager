# Product Manager (Lab 04)

## Менеджер товарів

**Менеджер товарів** — це багатошаровий WPF-застосунок для обліку складів і товарів, що належать до цих складів. Кожен склад містить набір товарів, які логічно з ним пов’язані.

У застосунку реалізовано повний цикл взаємодії з даними: створення, редагування, перегляд, фільтрація, сортування та видалення сутностей. Для кожного товару зберігаються його основні дані, наприклад назва, кількість, ціна, категорія та опис, а також обчислюване поле вартості. Для складу також обчислюється загальна вартість усіх товарів, що до нього належать.

На відміну від попередніх лабораторних робіт, у цьому проєкті використовується реальне файлове сховище. При першому запуску застосунок автоматично заповнює сховище початковими даними, а надалі працює вже зі збереженими змінами.

### Архітектура та структура проєкту

1. **ProductManager.StorageModels**

    У цьому проєкті знаходяться моделі та перелічення, які описують сутності сховища.

    - `Enums.Location.cs`
    - `Enums.ProductCategory.cs`
    - `Entities.ProductEntity.cs`
    - `Entities.WarehouseEntity.cs`

    `ProductEntity` описує товар, який належить певному складу.  
    `WarehouseEntity` описує склад, у якому можуть зберігатися товари.

2. **ProductManager.Repositories**

    Цей проєкт відповідає за роботу зі сховищем.

    - `IStorageRepository.cs`
    - `StorageRepository.cs`
    - моделі збереження даних у файловому сховищі

    Репозиторій виконує асинхронну взаємодію з реальним сховищем, забезпечує зчитування, збереження, оновлення та видалення даних. Також тут реалізовано початкове заповнення сховища даними при першому запуску застосунку.

3. **ProductManager.Services**

    У цьому проєкті знаходяться сервіси та DTO-моделі, які використовуються UI шаром.

    - `IStorageService.cs`
    - `StorageService.cs`
    - DTO-моделі для складів і товарів

    Сервіси отримують дані з репозиторію, перетворюють їх у зручний для UI вигляд та реалізують основну прикладну логіку застосунку.  
    Взаємодія зі сховищем відбувається асинхронно через сервіси.

4. **ProductManager.UIModels**

    Цей проєкт містить ViewModel-и, команди, логіку навігації та логіку взаємодії між сторінками застосунку.

    Тут реалізовано:
    - відображення списку складів
    - пошук, фільтрацію і сортування складів
    - перегляд детальної інформації про склад
    - редагування складу
    - перегляд списку товарів конкретного складу
    - пошук, фільтрацію і сортування товарів
    - додавання нового товару
    - додавання вже існуючого товару з іншою кількістю
    - відкриття детальної інформації про товар
    - редагування товару
    - видалення складів і товарів

    Також у ViewModel-ах реалізовано обчислювані поля вартості товару та загальної вартості товарів на складі.

5. **ProductManager.UI**

    У цьому проєкті знаходиться графічний інтерфейс застосунку, побудований на WPF.

    UI працює за принципом MVVM і містить:
    - головне вікно застосунку
    - сторінки для списку складів
    - сторінки для деталей складу
    - сторінки для деталей товару
    - елементи навігації між сторінками
    - індикатори стану асинхронних операцій

    Застосунок використовує лише одне головне вікно, а навігація відбувається через зміну сторінок, а не через відкриття нових вікон.

### Основні можливості застосунку

- перегляд списку всіх складів
- пошук, фільтрація і сортування складів
- додавання, редагування та видалення складів
- перегляд детальної інформації про склад
- перегляд товарів, що належать складу
- пошук, фільтрація і сортування товарів
- додавання нових товарів
- додавання вже існуючих товарів із заданням окремої кількості
- перегляд, редагування та видалення товарів
- автоматичне збереження змін у файловому сховищі
- початкове заповнення сховища при першому запуску
- асинхронна робота зі сховищем без блокування UI

### Особливості реалізації

У проєкті дотримано принципів багатошарової архітектури, Single Responsibility, Inversion of Control та Dependency Injection.  
UI шар не працює напряму зі сховищем, а взаємодіє лише із сервісами.  
Сховище зберігає цілісність даних: при видаленні складу видаляються і всі товари, що йому належать.

Окрему увагу приділено асинхронності. Операції завантаження, збереження, оновлення та видалення виконуються асинхронно, а під час їх виконання UI блокує інші дії та показує індикатор прогресу.

### Запуск проєкту

Щоб запустити проєкт, необхідно:

1. Відкрити solution у Visual Studio
2. Обрати WPF UI проєкт як `Startup Project`
3. Запустити застосунок

Після першого запуску сховище буде автоматично створене та заповнене початковими даними.
